# 考题二 需求澄清：FastAPI 记账接口

## 1. 目标

基于 FastAPI 实现一个简易记账 HTTP 服务，支持新增流水、按条件筛选分页查询、按日期区间汇总收入 / 支出 / 结余。数据采用进程内存存储，所有非法输入返回 4xx 状态码与结构化错误信息。

## 2. 输入

### 2.1 新增流水 `POST /records`

请求体 JSON 字段：

| 字段 | 类型 | 含义 | 约束 |
|---|---|---|---|
| amount | 数值 | 金额 | 必须大于 0，不允许为 0、负数或非数值 |
| type | 字符串 | 类型 | 只能为 `income`（收入）或 `expense`（支出） |
| category | 字符串 | 分类 | 非空，长度至少 1 个字符，例如 餐饮、工资、交通 |
| date | 字符串 | 日期 | 格式 `YYYY-MM-DD`，可被日期解析器识别，不接受非法日期 |

### 2.2 筛选查询 `GET /records`

查询参数（全部可选，不传则不参与过滤）：

| 参数 | 含义 | 约束 |
|---|---|---|
| type | 按类型筛选 | `income` / `expense`，非法值返回 4xx |
| category | 按分类精确筛选 | 字符串，非空才生效 |
| start_date | 起始日期（含） | `YYYY-MM-DD` |
| end_date | 结束日期（含） | `YYYY-MM-DD` |
| page | 页码 | 从 1 开始，默认 1，必须为正整数 |
| page_size | 每页条数 | 默认 10，最大 100，必须为正整数 |

### 2.3 汇总 `GET /summary`

查询参数：

| 参数 | 含义 | 约束 |
|---|---|---|
| start_date | 起始日期（含） | 必填，`YYYY-MM-DD` |
| end_date | 结束日期（含） | 必填，`YYYY-MM-DD` |

## 3. 输出

### 3.1 新增流水响应（201 Created）

返回刚入库的流水：

```json
{
  "id": 1,
  "amount": 35.5,
  "type": "expense",
  "category": "餐饮",
  "date": "2026-11-01"
}
```

### 3.2 列表响应

```json
{
  "total": 2,
  "page": 1,
  "page_size": 10,
  "items": [
    {"id": 1, "amount": 35.5, "type": "expense", "category": "餐饮", "date": "2026-11-01"}
  ]
}
```

### 3.3 汇总响应

```json
{
  "start_date": "2026-11-01",
  "end_date": "2026-11-01",
  "total_income": 5000.0,
  "total_expense": 135.5,
  "balance": 4864.5
}
```

其中结余 `balance = total_income - total_expense`。区间内无流水时，三项金额均为 0，不报错。

## 4. 校验规则

1. 金额 `amount` 必须为正数（`> 0`），否则 422。
2. 类型 `type` 只能是 `income` 或 `expense`，其他取值 422。
3. 分类 `category` 不能为空字符串或全空格，否则 422。
4. 日期必须是合法 `YYYY-MM-DD`，非法格式或不存在的日期（如 2026-13-40）422。
5. 分页参数 `page`、`page_size` 必须为正整数，`page_size` 不超过 100，否则 422。
6. `GET /summary` 缺少 `start_date` 或 `end_date`、日期格式非法，返回 4xx。

## 5. 数据存储与并发

- 本题允许内存或 SQLite；本方案选用**进程内存列表 + 线程锁**，服务重启后数据清空，符合课堂练习定位。
- 所有写入（新增流水）在同一把互斥锁内完成，保证自增 ID 与列表更新的原子性，并发写入不会出现 ID 冲突或列表错乱；读取在锁内快照复制后返回，避免遍历期间列表被修改。

## 6. 边界与异常

- 列表筛选结果为空：`items` 为空数组，`total` 为 0，不报错。
- 汇总区间内无流水：收入、支出、结余均为 0。
- 非法参数：统一返回 4xx 状态码，响应体为结构化错误信息 `{"detail": [...]}`，字段级说明错误位置与原因。
- 不把服务地址、外部数据库、第三方密钥写入代码；仅本地 `127.0.0.1` 启动。

## 7. 验收标准

1. 服务可启动，`POST /records`、`GET /records`、`GET /summary` 可正常调用。
2. 金额非正、类型非法、日期格式错误、分类为空、分页非法等校验用例返回预期 4xx 状态码。
3. pytest 覆盖正常新增、筛选分页、区间汇总与上述异常用例，测试全部通过。
4. 汇总数值与人工手算一致；并发写入下 ID 不重复（在文档中说明锁的保证方式）。
