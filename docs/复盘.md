# 复盘

## 考题二：FastAPI 记账接口

### 哪些环节交给 AI

1. **pydantic 数据模型**：AI 给出 `RecordIn`、`RecordOut`、`SummaryOut` 的字段、类型与约束写法。
2. **内存仓库骨架**：AI 给出 `RecordStore` 的锁、自增 ID、查询过滤与区间汇总基本结构。
3. **FastAPI 路由**：AI 给出三个接口的参数声明、分页切片、统一 422 错误处理器与 `create_app` 工厂。
4. **pytest 用例框架**：AI 给出 TestClient 初始化、数据种子函数与分组用例骨架。

### 哪些自己拍板

1. **需求澄清全部先手写**：目标、字段约束、筛选条件、分页边界、汇总口径、并发要求，先写进 `需求澄清_考题二.md` 再开始编码，没有直接让 AI 猜需求。
2. **存储选型**：在内存与 SQLite 之间选择内存列表 + 线程锁，理由是课堂练习无需落盘、测试隔离简单；并在 README 写明替换为数据库的条件。
3. **接口字段命名**：请求体使用英文 `amount / type / category / date`，类型取值 `income / expense`，错误提示用中文，兼顾接口规范与可读性。
4. **测试隔离方式**：确认每个用例通过 `create_app(RecordStore())` 获得全新存储，用例之间不共享数据。
5. **用例覆盖范围**：在题目要求的"正常 + 至少 2 个边界 / 异常"基础上，补齐类型非法、日期非法、分类全空格、列表查询类型非法、分页非法、汇总缺参、空区间等共 13 个用例。

### 哪些风险做了人工审查

1. **并发 ID 冲突风险**：审查 `RecordStore.add`，确认自增 ID 与列表追加在同一把 `Lock` 内完成，并发写入不会重复编号；查询先复制快照，不在遍历期间持有锁修改内部列表。
2. **非法输入崩溃风险**：审查 pydantic 模型与 `Query` 约束，确认金额非正、类型非法、日期非法、分类为空、分页越界都被框架拦截为 422，不会进入业务逻辑抛未捕获异常。
3. **浮点金额误差风险**：人工补充金额入库 `round(..., 2)`，汇总结果同样保留两位小数，避免浮点累加出现长尾小数。
4. **错误信息结构化风险**：审查自定义异常处理器，确认 422 响应统一为 `detail` 数组，逐条给出字段与原因，而不是框架默认的英文原始堆栈。
5. **环境隔离风险**：依赖安装在项目内 `.venv`，`.gitignore` 已排除虚拟环境、缓存与 IDE 配置，避免把本机路径和缓存提交进仓库。

### 与考题一过程上的对照改进

1. 先写需求澄清再编码，顺序与考题一保持一致，避免边写边改需求。
2. 每完成一个模块立即跑对应测试，而不是全部写完再统一调试。
3. 两轮 pydantic 报错（字段名遮蔽类型、`strip_whitespace` 弃用）都当场记录进 AI 对话记录，没有事后补写。

### 如果重做会改进什么

1. 可以把内存存储抽象成接口，后续切换 SQLite 时路由层不用改动。
2. 为汇总接口补充日期区间倒置（start_date 晚于 end_date）的校验与提示。
3. 增加并发写入的压测用例，用多线程同时新增，直接验证 ID 不重复。
